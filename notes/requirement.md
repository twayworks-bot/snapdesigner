## [REQ-001] 1인 기업 홈페이지 디자인 스타일 헬퍼 & 템플릿 패키지 프로젝트 초기 정의 (2026-10-29 23:16)

### 1. 프로젝트 개요 및 목적
- **대상 사용자**: 1인 기업, 프리랜서, 크리에이터, 소규모 스튜디오 및 중소형 기업
- **핵심 목적**: 자사 홍보 및 광고용 홈페이지 제작 시, 기업의 정체성(Identity)과 톤앤매너(Tone & Manner)를 정의하고 그에 부합하는 디자인 스타일을 선택하여 즉시 웹앱/홈페이지 개발을 시작할 수 있도록 **디자인 템플릿 패키지 및 가이드**를 제공하는 디자인 Helper 앱 구축.

### 2. 핵심 스타일 메타데이터 정의 요구사항
각 디자인 스타일은 다음 항목을 명확히 포함해야 함:
1. **디자인 스타일명**: 직관적이고 정체성이 드러나는 국/영문 명칭 및 식별 코드
2. **디자인 템플릿 정의**: 레이아웃 시스템, 네비게이션, 히어로(Hero) 영역, 섹션 구성, 카드/버튼/보더/여백 등 UI/UX 구조적 특징
3. **디자인 정체성 키워드**:
   - **형용사 (Adjectives)**: 브랜드의 분위기, 인상, 성격을 나타내는 어휘
   - **동사 (Verbs)**: 브랜드가 고객에게 제공하는 행동, 가치 전달 방식을 나타내는 어휘
   - **톤앤매너 (Tone & Manner)**: 광고 카피라이팅 및 시각적 커뮤니케이션 어조
4. **색상 스타일 (Color Palette)**: Primary, Secondary, Accent, Background, Surface, Text 컬러(HEX 코드)와 배색 비율 및 심리적 효과
5. **폰트 스타일 (Typography)**: 제목(Heading), 본문(Body), 포인트(Accent/Mono) 추천 폰트 조합 및 웨이트/행간/자간 스타일 가이드
6. **적합 업종 및 활용 가이드**: 해당 스타일이 가장 큰 광고 효과를 내는 1인 기업/중소기업 분야 및 샘플 슬로건

### 3. 초기 구축 목표
- 대표 디자인 스타일 **10개**를 선정하고 각각의 메타데이터를 상세히 정의 및 기록.
- 기록된 메타데이터를 기반으로 사용자가 스타일을 탐색·비교·선택하고, 웹앱 개발에 바로 참조할 수 있는 템플릿 패키지(CSS 변수, 디자인 토큰, HTML/CSS 보일러플레이트, AI 프롬프트/가이드 등)를 제공하는 MVP(Minimum Viable Product) 정의 및 세부 개발 계획 수립.

### 4. 문서 및 산출물 기록 규칙
- 모든 요구사항 누적 기록: `notes/requirement.md`
- 매번 개발 요구사항과 요약 기록: `notes/history.md`
- 사용자 원본 요구사항과 계획 기록: `notes/req_YYYYMMDDHHmm.md`
- MVP 정의 및 개발 세부 계획 기록: `notes/plan_YYYYMMDDHHmm.md`
- 산출물 생성 기록: `notes/result_YYYYMMDDHHmm.md`

1. **정체성 기반 디자인 템플릿 선택 및 샘플 홈페이지(TheWayWorks) 실시간 변경**:
   - 기업의 정체성(형용사, 동사, 타깃 업종)에 맞는 디자인 템플릿(10대 대표 스타일)을 탐색·선택하는 기능.
   - 스타일 선택 시 **TheWayWorks 샘플 홈페이지 전체(회사 CI 로고 마크, 컬러 팔레트, 타이포그래피, 카드/보더/곡률/그림자, 히어로 및 섹션 분위기, 톤앤매너 슬로건)**가 선택된 디자인 템플릿으로 실시간 변환(Live Restyling)되어 비교·검토 가능해야 함.
2. **디자인 패키지 참조 API 엔드포인트 제공**:
   - 외부 웹앱이나 AI 코딩 도구가 선택된 디자인 템플릿과 패키지를 참조할 수 있는 REST API 엔드포인트 제공:
     - `GET /api/styles` (전체 스타일 목록 및 정체성 키워드 필터링)
     - `GET /api/styles/{style_id}` (단일 스타일 상세 메타데이터)
     - `POST /api/styles/recommend` (형용사/동사/업종 기반 최적 디자인 템플릿 추천)
     - `GET /api/styles/{style_id}/tokens.css` (CSS Custom Properties 디자인 토큰 스타일시트 직접 참조)
     - `GET /api/styles/{style_id}/package` (메타데이터 + CSS 토큰 + CI/AI 프롬프트 가이드 통합 패키지 JSON 참조)
3. **디자인 템플릿 패키지 다운로드 기능 (`.zip`)**:
   - 선택된 디자인 스타일이 적용된 디자인 템플릿 패키지(`design-tokens.css`, `style-metadata.json`, `CI_AND_STYLE_GUIDE.md`, 그리고 해당 스타일이 적용된 TheWayWorks 샘플 홈페이지 보일러플레이트 `index.html`, `styles.css`, `app.js`, `img/`)를 `.zip` 압축 파일로 즉시 다운로드(`GET /api/styles/{style_id}/download`)하는 기능 제공.
4. **단계적 진행**:
   - 본 개발 계획서를 수립하여 사용자 리뷰를 거친 후 실제 시스템 구현 진행.

## [REQ-007] 웹사이트 제작 지원도구 UI/UX 전면 재구성 및 4단계 사용자 흐름 설계 (2026-11-07 14:06)

### 1. 요구사항 배경 및 목적

- 처음부터 무거운 전체 샘플 홈페이지를 노출하는 대신, **첫페이지 안내 & 대표 타일 탐색 ➔ 상세 가이드 & 표준 대표페이지 경량 프리뷰 ➔ (선택 시) 고급 스타일×레이아웃 조합 및 신규 생성 관리 ➔ 최종 샘플 디자인 적용 후 전체 샘플 홈페이지 네비게이션 확정**의 일관된 흐름으로 재구성.

### 2. 6대 핵심 UI/UX 개편 요구사항
1. **첫째 (첫 페이지 목적·사용법·활용방법 디자인)**:
   - 지원도구의 첫 페이지는 도구의 목적, 단계별 사용법, 그리고 활용 방법(웹 제작, AI 바이브코딩, API/토큰 활용)에 대한 세련된 디자인을 제공.
2. **둘째 (첫 페이지 대표 스타일·레이아웃 타일 10~20개 한눈에 보기)**:
   - 첫 페이지에서 대표 스타일 가이드 타일 10개(및 대표 레이아웃/추천 조합 포함 10~20개)를 표준 구성요소(미니 메뉴배치·히어로·컬러·폰트·키워드)가 한눈에 보이도록 타일 형태로 제공.
3. **셋째 (타일 선택 시 상세 설명, 샘플 프리뷰 및 템플릿 다운로드)**:
   - 대표 타일 선택 시 자세한 스타일·레이아웃 가이드 설명을 볼 수 있고, 이를 통해 샘플 홈페이지를 검토·적용하며, 해당 스타일 가이드로 만들어진 템플릿 패키지(`.ZIP`)를 즉시 다운로드할 수 있어야 함.
4. **넷째 (고급 선택도구 — 디자인 스타일 × 레이아웃 조합 관리 페이지)**:
   - 첫 페이지에서 대표 타일 외에 선택하기 위한 `[고급 선택도구]`를 선택하면, 스타일 가이드와 레이아웃 조합으로 구성된 **디자인 스타일 관리 페이지**를 제공하여 다양한 조합을 선택·생성하고 웹사이트 스타일을 한눈에 비교할 수 있어야 함.
5. **다섯째 (톤앤매너 중심 스타일 가이드 vs 메뉴 배치·뷰 스타일 중심 레이아웃 구분)**:

6. **여섯째 (선택 전 대표 페이지 경량 프리뷰 vs 최종 선택 후 전체 페이지 네비게이션)**:
   - 최종 스타일 선택(적용) 전에는 메뉴 구성, 레이아웃, 톤앤매너 등 **표준 구성을 기반으로 한눈에 볼 수 있는 몇 개의 대표 페이지 구성(경량 프리뷰)**을 통해 검토하고, 최종 샘플 디자인 적용 후에는 **전체 샘플 홈페이지의 모든 메뉴를 네비게이션**하며 최종 확정할 수 있도록 구성.
   - 고급 관리 기능을 통해 상세 요구사항에 맞게 고르거나 신규 요구사항에 맞게 생성한 디자인 역시 **[프리뷰 구성 ➔ 샘플 홈페이지 전체 적용 ➔ 최종 확정]**까지 일관된 흐름으로 이어져야 함.
